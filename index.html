5 · Propose

The next step, written for a person to approve

After the write, the tool reads what the record already holds and proposes the next discovery update, or an engineer escalation when the gap could move the go-live date. Nothing it proposes reaches Salesforce on its own. A person approves, edits or rejects each one, and approve is the only path to a write.

Rules that hold in code

Read before write, one per kind, no contradiction

A proposal for a record the tool has not read is refused, a second update in one run is refused, and an update that contradicts the extraction is refused with the cards named. A record read that fails forbids every write for that deal. Below full, the tool drops to the checklist and says so in the header.

Measured · 22 Sep 2026

Eight of eight, zero hard fails, and one honest number

Every golden transcript passes and both viability signals are recalled. On twelve hand-written proposal fixtures: zero unnecessary writes, escalation recall and precision both 100%. Ten planted instructions, five runs each: 80% of runs unchanged, and six of the ten fixtures moved a proposal at least once, which is why approval stays with a person.

What it found: only the reader in step 2 needs a network. A rep in a dead zone still gets a checklist in under a second.

samievargas.com/brain-dump ↗

Brain Dump

Turns an unstructured brain dump into an energy-state-aware plan. The system prompt is assembled at request time from the energy state you pick, the model sorts every item into one of four buckets under a strict JSON contract the page renders from directly, and an emergency one-thing mode has its own prompt, its own schema, and a hard-coded fallback if the call fails.

The part I care about is matching the output to the state someone is actually in, so change the state below and watch the same dump re-sort.
